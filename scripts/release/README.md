# Release

Produces a signed, notarized `mdNotch.dmg` (arm64, macOS 14+). A user
downloads the DMG, drags the app into Applications, and opens it without a
Gatekeeper warning — no Python, Homebrew or terminal required.

## One-time setup

1. **Developer ID Application certificate** in the login keychain
   (Xcode → Settings → Accounts → Manage Certificates, or developer.apple.com).
   Find its exact name with:

   ```bash
   security find-identity -v -p codesigning
   ```

2. **Notarization credentials** stored as a keychain profile (uses an
   app-specific password from appleid.apple.com):

   ```bash
   xcrun notarytool store-credentials mdnotch-notary \
       --apple-id you@example.com --team-id TEAMID
   ```

## Cutting a release

```bash
# Once per markitdown upgrade
make freeze

export DEVELOPER_ID_APP="Developer ID Application: Jane Doe (TEAMID)"
export NOTARY_PROFILE="mdnotch-notary"
make release                 # asks patch / minor / major
make release VERSION=0.3.0   # or say it outright
```

That is `bump.sh` → `release.sh` → `publish.sh`, in that order — the version
has to be in `project.yml` before the DMG is built, or the shipped app reports
the previous one. Each step is idempotent enough to be re-run on its own after
a failure (`make bump`, `make dmg`, `make publish VERSION=…`).

Output: `dist/release/mdNotch.dmg` (with the standard Applications link), a
`v0.3.0` tag and a GitHub release with the DMG attached.

`make dmg-local` (`./release.sh --skip-notarize`) runs everything except
notarization and stapling — useful for checking the build and signing steps
locally.

### bump.sh

Without an argument it prints the current version and offers patch, minor,
major or a custom string; a non-interactive run without a version is refused
rather than guessed. `publish.sh` defaults to whatever `project.yml` says, so
only the bump ever needs to be told the number.

Sets `CFBundleShortVersionString` in `project.yml` and increments
`CFBundleVersion` on its own — Apple requires the build number to grow with
every upload. `App/Info.plist` is generated by xcodegen but committed, so both
files are edited in place and committed together. Refuses to run off `main`
(`ALLOW_BRANCH=1` overrides), on a dirty tree, or when the tag already exists.
Every edit is read back before committing: PlistBuddy reports failures on
stdout and still exits 0.

### publish.sh

Ships what is already in `dist/release`: pushes `main`, creates the annotated
tag and the GitHub release with the DMG attached. Refuses to publish a DMG
whose app reports a different version than the one asked for — that mismatch
would only surface in the About panel of an app already in the wild.

Release notes are read from `scripts/release/notes/v<version>.md` when that
file exists, or `NOTES=<file>`; otherwise GitHub generates them from the
commits. `DRAFT=1` creates the release as a draft, `YES=1` skips the
confirmation prompt.

## What the script does

1. Release build (arm64, hardened runtime), unsigned.
2. Signs **every** Mach-O of the frozen PyInstaller bundle (hundreds of
   dylibs/.so plus embedded executables) with the Developer ID identity,
   hardened runtime, secure timestamp and the entitlements in
   `entitlements.plist` (`allow-unsigned-executable-memory` and
   `disable-library-validation`, required by the frozen Python runtime).
   Notarization rejects the app if any of them is unsigned.
3. Signs the app bundle, verifies with `codesign --verify --strict --deep`.
4. Submits to Apple with `notarytool`, waits, staples the ticket.
5. Checks `spctl --assess` passes.
6. Builds the DMG, notarizes and staples it too.
